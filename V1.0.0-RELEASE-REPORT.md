# Life RPG v1.0.0 — Final Release Report

**Decision: READY FOR 1.0**

Life RPG v1.0.0 is published on GitHub. The final tagged source commit adds the
1.0.0 metadata and release documentation to the Phase 13 Release Candidate; the
release cut did not require runtime, gameplay, architecture, persistence,
migration, UI-system, or dependency-modernization changes.

## Supported platform scope

- **Linux x86_64**, with Ubuntu 22.04 (Jammy, glibc 2.35) as the minimum tested
  baseline.
- Compatible newer Linux systems need GTK 3 and WebKitGTK 4.1; other
  distributions, older baselines, and other architectures are not certified.
- Windows and macOS are not supported by this release. Screen-reader
  certification and formal WCAG conformance were not performed.

The Debian package identifies `life-rpg 1.0.0 amd64` and declares dependencies
on `libwebkit2gtk-4.1-0` and `libgtk-3-0`. The AppImage is an x86-64 ELF bundle.

## Verification performed

- **Phase 13 baseline:** all Rust (150) and frontend (124) tests passed on the
  Phase 12 parent before scenario additions; production build and Phase 13 RC
  package checks were also completed.
- **Full Rust workspace on the RC validation changes:** 158 passed, 4 ignored,
  0 failed across the workspace test binaries. This included populated-world,
  medium-world performance, migration upgrade, backup boundary, and subprocess
  termination/recovery tests.
- `cargo fmt --all -- --check`, `cargo check --workspace`, and `git diff --check`:
  passed.
- Frontend TypeScript typecheck, Vitest suite, and production Vite build: passed.
- `npm audit --audit-level=low`: zero frontend vulnerabilities.
- `cargo audit`: no blocking advisory; two existing informational RustSec notices
  remain: `glib 0.18.5` unsoundness (`RUSTSEC-2024-0429`) and unmaintained
  `proc-macro-error 1.0.4` (`RUSTSEC-2024-0370`). Both are transitive and were
  recorded as non-blocking in the Phase 13 report.
- Fresh Tauri bundles were built from the 1.0.0 source inside the isolated
  Ubuntu 22.04 Jammy userspace.

See the [Phase 13 validation report](docs/PHASE-13-REPORT.md) for detailed
scenario, persistence, crash-injection, migration, performance, and baseline
evidence.

## Fresh release-artifact smoke test

The freshly built `.deb` was installed in Jammy; the freshly built AppImage was
launched with `--appimage-extract-and-run` there. In isolated profiles, the `.deb`
walkthrough verified:

1. first-run launch and Player world creation;
2. keyboard-only focus traversal and Enter activation of navigation and the
   Workspace action;
3. Player Hub, Workspace, and System Health navigation;
4. application-reported version **1.0.0**;
5. verified backup creation using the UI. The app reported the selected local
   path and `Backup created and verified (schema v17, 896.0 KiB)`;
6. a normal Alt+F4 exit under Openbox-managed Xvfb, followed by reopening the
   existing `Life RPG 1.0.0 Smoke World` from the same profile;
7. on reopening, active-world data remained visible and System Health reported
   SQLite schema v17, WAL, foreign keys enforced, and a committed write/read
   round-trip.

The AppImage independently rendered the first-run screen and exited normally
under Openbox-managed Xvfb. A preliminary direct window-destruction attempt in
Xvfb without a window manager caused a GDK `BadDrawable`; the shutdown check was
repeated with Openbox and passed through the normal window-manager close path.

## Known limitations carried forward

Backups are local and unencrypted. SHA-256 detects accidental corruption but is
not a signature and does not authenticate the creator. There is no cloud sync,
accounts, multiplayer, mobile support, or background scheduling. Formal
accessibility certification and screen-reader testing were not performed. The
two documented informational RustSec notices remain unchanged.

## Final status

**READY FOR 1.0** — the public v1.0.0 release is published, the tag resolves to
the tested release commit, all required Linux assets are attached, and checksums
verified against the actual downloaded release files.
